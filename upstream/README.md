# LiteLLM Python port

The Go port follows the public Python implementation in LiteLLM. The initial reference is `v1.85.0` at the commit in [litellm.ref](litellm.ref), which also matches the revision of Minato's existing LiteLLM image. This is the source baseline for the port. Compatibility is verified by behavior and recorded per area. [LiteLLM v1.85.0](https://github.com/BerriAI/litellm/tree/v1.85.0)

The upstream MIT license notice is included with this port. LiteLLM's `enterprise/` directory has separate terms for use and distribution. [MIT notice](LICENSE.litellm) · [LiteLLM Enterprise license](https://github.com/BerriAI/litellm/blob/v1.85.0/enterprise/LICENSE.md)

Run `python tools/sync-litellm-openapi.py --show-unlisted` to regenerate the Go OpenAPI snapshot and list upstream HTTP operations absent from it. The inventory tracks documentation coverage. `GET /routes` exposes the subset of that inventory enabled by the current configuration. Confirm request, authorization and response behavior separately, including WebSocket routes and native operations outside OpenAPI.

## Verify protocol behavior

Full proxy parity remains open. Cross-proxy HTTP checks cover model discovery and selected chat paths. Provider fixtures and Go regression tests cover the additional operations in the table. The route inventory also includes management, policy, and integration surfaces that still need implementations and behavior checks.

Go serves provider and end-user spend totals from its PostgreSQL accounting records. The provider report uses recorded provider names for both current and imported requests. User-bound keys see their own provider and model totals. Priced customer requests insert the spend record and increment the customer counter in one database operation, using the request ID to prevent duplicate charges.

Budget creation rejects duplicate IDs and negative monetary amounts and computes the initial reset for a configured duration. Updates apply only supplied fields in one SQL statement. Budget info accepts multiple IDs, list returns an array, and settings returns field metadata for the Dashboard.

The native management APIs include paginated model, user and team info, batch key lookup by key or alias, and paginated key aliases. Key lookup and aliases are scoped to the caller's user and teams. Partial model updates preserve omitted settings. Model listing supports filtering by creator and team grants, and sorting by name, creation time, update time, token cost and managed status. Team-owned model administration, access group expansion and organization-admin delegation remain open.

The release enables the implemented proxy APIs by default. An exact replacement claim for the pinned LiteLLM release requires passing the same request and persistence fixtures for its public API routes, provider adapters and Dashboard API calls. Deployments can disable management and extended provider APIs independently and enable route publication with a separate token.

The native Dashboard image reuses the static export from the pinned LiteLLM image. The Go server serves the UI, supports administrator and internal-user password login with expiring browser credentials, and honors the management API switch. Administrators set internal-user passwords via the user management API. The proxy stores scrypt hashes and imports LiteLLM scrypt and legacy SHA-256 hashes. Password changes revoke existing password sessions for that user. An isolated HTTP smoke test verified the shell, its scripts, administrator login, model discovery and virtual key creation. The internal-user fixture verifies persistence, read-only access and session revocation. Browser flows across all Dashboard pages and control-plane login remain open.

Go supports invitation creation, lookup, update, deletion and the two-step Dashboard onboarding exchange. An onboarding token is bound to an invitation and user ID and expires within 15 minutes. Claiming an invitation updates the password, consumes the invitation and issues the scoped browser credential in one access-state write. PostgreSQL import preserves invitation records. The HTTP fixture checks a valid claim, owner binding, rejection of a replay after restart and password login after onboarding. An isolated Go binary serving the pinned Dashboard export returned the onboarding HTML and completed the same exchange over HTTP. Delegated invitation creation and deletion by organization or team administrators remain open.

Deployments that require upstream behavior can set `LITELLM_GO_COMPATIBILITY_UPSTREAM` to a LiteLLM service and select which paths run natively in Go. When every path uses the compatibility upstream, that LiteLLM service owns keys, state and provider behavior. Go serves `GET /model/settings` and `GET /utils/supported_openai_params` from authenticated catalogs generated from the pinned Python release. Parameter coverage includes catalog models that can be inspected without credentials.

An isolated Minato smoke run verified registration, publication, the OpenAI SDK, fallback, SSE, rollback, key revocation, audit, usage and replay with the Go runtime. It used a synthetic upstream and a temporary PostgreSQL database. Provider fixture coverage and Python behavior comparisons are recorded below.

With both proxies configured for the same synthetic OpenAI endpoint, LiteLLM `v1.85.0` and the Go proxy returned matching model IDs, object types, creation timestamps and providers for `/models`, `/v1/models` and the corresponding model-detail routes. The compatibility listener matched 18 live HTTP probes against the pinned upstream, covering model discovery, the OpenAPI document, Dashboard access, authorization, token utilities and streamed and non-streamed inference. Four native Chat Completions cases matched upstream status and successful token usage for ordinary requests, O-series temperature errors, dropped parameters and explicit parameter overrides. Assistant content and total token counts also matched for versioned, unversioned and Azure-style chat completion paths.

The health fixture verifies native Responses, image generation, multipart transcription and OCR through the authenticated health endpoint. The transcription WAV and inline OCR PDF are taken from LiteLLM `v1.85.0` and embedded in the Go binary. [Upstream probe handlers](https://github.com/BerriAI/litellm/blob/v1.85.0/litellm/litellm_core_utils/health_check_helpers.py)

With `general_settings.use_shared_health_check` and router Redis configured, Go replicas share a deployment probe using a Redis lease and a cached result. The isolated Redis fixture verifies that two replicas issue one upstream request and both report the result. The lease expires on worker loss, only its owner can publish, and Redis errors fall back to local probes. Redis diagnostics report connectivity. Go uses a separate namespace from the LiteLLM pod-level lock.

